Migrating from 0.3

Version 0.4 is a redesign around one data model (values flow with >>, files are declared on steps) and one resolution model for wildcards. Most pipelines need small edits.

Behaviour changes

  • Steps without declared outputs always run. In 0.3 they were skipped on later runs and passed the string "up to date (not re-run)" downstream.
  • A changed command reruns the step, even when the outputs are newer than the inputs. The state file is now a small text file; the old 8 MB binary file is ignored and replaced.
  • Shell commands use bash -e -o pipefail. A failure inside a pipe now fails the step. Commands like zcat x.gz | head need set +o pipefail; in front.
  • Outputs of a failed step are deleted, and output directories are created automatically, so mkdir -p in commands is no longer needed.
  • Workflows rebuild stale targets. In 0.3 an existing target was treated as done even when its inputs had changed.
  • Function steps adapt to their arity. A zero-argument function after another step is called without arguments instead of failing.
  • A function rule receives one argument per declared input, then the outputs (f(input, output) as before, f(r1, r2, output) for two inputs). The (inputs, outputs, wildcards) builder form is gone; use a string template with {wildcard} placeholders, or derive values from the paths.
  • jobs is a global cap on busy CPU threads (default: all CPU threads), counting each step's threads. In 0.3 it limited branches per parallel node, so nested parallelism multiplied.
  • run returns a RunResult. It still behaves as a vector of StepResults, and adds success, value and duration. StepResult gained label and status.
  • Errors in user code are reported as failed steps instead of being thrown, for example a ForEach block that returns nothing, or a Branch condition that throws.
  • The operators do not change Base behaviour any more. $`a` & `b`$ is Base's AndCmds again. Use sh"a" & sh"b", or wrap commands in steps.
  • Resources are limits. mem_mb (MiB) and the new timeout are enforced by a resource guard process: a command that uses more memory or runs longer is terminated. Steps also wait for free memory, and the pipeline's commands are stopped and requeued before the computer runs out of memory. run(...; guard=false) turns this off. See Resource limits and safety.
  • mem_mb defaults to 80% of the memory the process may use (it was half of the RAM), and steps without mem_mb are charged 256 MiB. jobs defaults to the CPUs the process may use, which respects container and cluster limits.
  • {threads} and {mem_mb} are filled in when a step starts, from what it was granted; a mem_mb above the run's budget is lowered to it. {mem_mb} in a step that declares no mem_mb is an error.
  • Commands must not leave processes behind. A step whose command exits while its background jobs still run fails, and the jobs are terminated; end such scripts with wait.
  • Commands run at nice 10 and see OMP_NUM_THREADS and similar variables set to their threads.
  • Julia 1.10 is the minimum version.
