SimplePipelines.SimplePipelines — Module
SimplePipelines

Incremental, parallel pipelines for shell commands and Julia functions, with Snakemake-style wildcard rules.

using SimplePipelines

# explicit steps
prep  = @step prep([] => "data.txt") = "seq 1 100 > {output}"
total = @step total("data.txt" => "total.txt") = "paste -sd+ {input} | bc > {output}"
run(prep >> total)

# wildcard rules: one step per sample found on disk
trim  = @rule trim("raw/{s}.fq.gz" => "trim/{s}.fq.gz") = "fastp -i {input} -o {output}"
align = @rule align("trim/{s}.fq.gz" => "bam/{s}.bam"; threads=8) =
    "bwa mem -t {threads} ref.fa {input} | samtools sort -o {output}"
run(trim >> align)

See @step, @rule, Workflow, run and check.

Steps

SimplePipelines.Step — Type
Step(work)
Step(name::Symbol, work; threads=0, mem_mb=0, timeout=0)
Step(name::Symbol, work, inputs, outputs; threads=0, mem_mb=0, timeout=0)

One unit of work. Usually built with @step.

work is one of:

  • a shell command: sh"..." or a String (run with bash -e -o pipefail);
  • a Cmd (backticks);
  • julia("script.jl ..."): Julia code in a separate, limited process;
  • a Julia function (runs inside this Julia process).

threads, mem_mb (MiB) and timeout (seconds) are limits: a command that uses more memory or runs longer is terminated, and steps only start when their resources fit. A Julia function runs inside this process and cannot be limited or stopped; use julia for heavy Julia code.

With declared inputs/outputs (the path form), a shell template may use {input}, {output}, {input[i]}, {output[i]}, {threads} and {mem_mb}, and a function is called with the paths: f(inputs..., outputs...). Without paths, a function receives the upstream value when it takes one argument, and nothing otherwise.

Declared paths make the step incremental: it is skipped when its outputs exist, are newer than its inputs and were made by the same command. Output directories are created before the step runs, and outputs left behind by a failed run are removed.

source
SimplePipelines.@step — Macro
@step name = work
@step name(inputs => outputs; threads=0, mem_mb=0, timeout=0) = work
@step name(inputs) = work
@step work

Create a named Step. When a path contains a {wildcard}, the result is a Rule (a step template) instead.

work is a shell command (sh"...", a String template, a Cmd), Julia code in a separate process (julia("script.jl ...")) or a function. A function call on the right-hand side is deferred until the step runs (@step load = read_table("x.csv")), except for command builders (sh(...), string(...), *, Cmd(...), pipeline(...), julia(...)). A function that returns a command has that command run. threads, mem_mb (MiB) and timeout (seconds) are limits; see Step.

@step hello = sh"echo hello"
@step sorted("data.txt" => "sorted.txt") = "sort {input} > {output}"
@step bam(["r1.fq", "r2.fq"] => "a.bam"; threads=8) = "bwa mem -t {threads} ref.fa {input} > {output}"
@step stats("a.bam" => "a.txt") = (bam, txt) -> write(txt, string(filesize(bam)))
@step align("raw/{s}.fq" => "bam/{s}.bam") = "bwa mem ref.fa {input} > {output}"   # a Rule

SimplePipelines.@sh_str — Macro
sh"command"
sh(command)

A shell command. The literal form does not interpolate $, so shell variables such as $HOME reach the shell untouched. Use sh("... $(x) ...") when the command needs Julia values.

sh"sort data.txt | uniq -c > counts.txt"
sh("bwa mem -t $(n) ref.fa $(sample).fq > $(sample).sam")

Shell commands run with bash -e -o pipefail, so a failure anywhere in a pipe fails the step. See also Shell.

source
SimplePipelines.sh — Function
sh(command::AbstractString) -> Shell

Same as sh"...", but takes an ordinary string so the command can interpolate Julia values: sh("samtools index $(bam)").

source
SimplePipelines.Shell — Type
Shell(script)

A shell script, run with bash -e -o pipefail -c script (or sh -e -c script when bash is not installed). Strict mode means a failing command, including one in the middle of a pipe, fails the step instead of being silently ignored.

Build one with @sh_str or sh.

source
SimplePipelines.julia — Function
julia(arguments)

Work that runs Julia code in a separate process, so it can be limited, measured and terminated like any command (Julia functions run inside this process and cannot be). arguments are the arguments of julia, with the same placeholders as shell templates; the process is started with this Julia, the active project, --threads={threads} and, when the step declares mem_mb, a matching --heap-size-hint. Your own flags come last and take precedence.

@step counts("reads.tsv" => "counts.tsv"; threads=4, mem_mb=8000) =
    julia("scripts/count.jl {input} {output}")

In the script, the paths are in ARGS.

source
SimplePipelines.with_resources — Function
with_resources(node; threads=0, mem_mb=0, timeout=0)

Default resources for every step inside node that does not declare its own: threads, mem_mb (a limit in MiB) and timeout (seconds). See Resource limits for how they are enforced.

SimplePipelines.AbstractNode — Type
AbstractNode

Supertype of everything run can execute: Step, the composite nodes built by >>, &, | and ^, ForEach and Workflow.

SimplePipelines.Sequence — Type
Sequence(nodes...)
a >> b

Run nodes one after another, stopping at the first failure. Each node receives the value of the previous one. The value of a sequence is the value of its last node.

source
SimplePipelines.Parallel — Type
Parallel(nodes...)
a & b

Run nodes concurrently; every node receives the same input. The value is the vector of the node values, in order. A failing branch does not stop the others.

source
SimplePipelines.Retry — Type
Retry(node, max_attempts=3; delay=0)
node^n

Run node again after a failure, up to max_attempts times, sleeping delay seconds between attempts.

source
SimplePipelines.Fallback — Type
Fallback(primary, fallback)
primary | fallback

Run fallback only when primary fails.

SimplePipelines.Branch — Type
Branch(condition, if_true, if_false)

Run one of two nodes. condition is called when the branch is reached, with the upstream value if it accepts one argument, and must return a Bool. See also @branch.

SimplePipelines.@branch — Macro
@branch condition if_true if_false

Branch with a condition written inline; it is evaluated when the branch is reached. @branch isfile("cache.bin") load compute is Branch(() -> isfile("cache.bin"), load, compute).

source
SimplePipelines.Timeout — Type
Timeout(node, seconds)

Fail if node has not finished within seconds. Shell commands still running at the deadline are terminated, including their child processes; steps that have not started yet are not started.

source
SimplePipelines.Force — Type
Force(node)

Run every step inside node even when its outputs are up to date.

SimplePipelines.ForEach — Type
ForEach(items) do item ... end
ForEach("pattern/{wildcard}.ext") do wildcard... end

Fan out: build one branch per item, or per file matching the pattern, when the pipeline runs. The block returns a step or node (a shell command or function is lifted to a step). Branches run in parallel; the value is the vector of branch values.

With a pattern, the block receives the wildcard values in order of appearance, and step names in the log are tagged with them (align[sample=A]). A pattern that matches no files is a failure; an empty collection is not.

ForEach(["A", "B"]) do s
    @step count = sh("wc -l $(s).txt")
end

ForEach("fastq/{sample}_R1.fq.gz") do sample
    @step trim = sh("fastp -i fastq/$(sample)_R1.fq.gz -o trim/$(sample).fq.gz")
end

Rules and workflows

SimplePipelines.Rule — Type
Rule(name, inputs, outputs, work; threads=0, mem_mb=0, timeout=0)

A step template whose paths contain {wildcards}. Usually built with @rule or with @step when the paths contain wildcards.

  • inputs: patterns, possibly gather(...) entries.
  • outputs: patterns; every output must use the same wildcards, and every (non-gather) input wildcard must appear in the outputs.
  • work: a shell template (String or sh"...") with placeholders {input}, {output}, {input[i]}, {output[i]}, {threads}, {mem_mb} and {wildcard} ({{x}} is a literal {x}), julia("script.jl {input} {output}") with the same placeholders, or a function called as f(inputs..., outputs...).
  • threads, mem_mb (MiB) and timeout (seconds): limits of every step the rule makes, as for Step.

A rule produces nothing by itself: use it in a Workflow, run it, or compose rules with >>/& (which merges them into one Workflow).

source
SimplePipelines.@rule — Macro
@rule name(inputs => outputs; threads=0, mem_mb=0, timeout=0) = work

Create a Rule: a step template with {wildcard} patterns.

@rule trim("raw/{s}_R1.fq.gz" => "trim/{s}.fq.gz"; threads=4) =
    "fastp -w {threads} -i {input} -o {output}"
@rule merge(gather("bam/{s}.bam") => "all.vcf") = "bcftools mpileup -f ref.fa {input} | bcftools call -mv -o {output}"
source
SimplePipelines.gather — Function
gather(pattern)

Rule input that collects every value of the wildcards that do not appear in the outputs. The values are found by tracing the rules back to existing source files, so gather works for files that other rules have not produced yet.

@rule merge(gather("bam/{sample}.bam") => "all.vcf") =
    "bcftools mpileup -f ref.fa {input} | bcftools call -mv -o {output}"

A function rule receives a gathered input as a Vector{String}; in a shell template {input[i]} expands to the space-separated list.

source
SimplePipelines.Workflow — Type
Workflow(rules...; targets=String[], name="workflow", filter=nothing)

A set of Rules and concrete Steps with declared outputs, plus the targets to build. A Workflow is a node: it is resolved into concrete steps when it runs, so it sees files produced by earlier steps.

Targets are concrete paths or patterns. A pattern target such as "bam/{s}.bam" builds every instance whose source files exist: wildcard values are discovered by tracing the rules back to files on disk. Without targets, the workflow builds the outputs of every rule that no other rule consumes (and runs rules that have no outputs once per matching input).

filter(w::Wildcards) -> Bool drops discovered wildcard values, e.g. filter = w -> w.sample != "control".

The value of a Workflow (passed downstream with >>) is the vector of target paths.

trim  = @rule trim("raw/{s}.fq.gz" => "trim/{s}.fq.gz") = "fastp -i {input} -o {output}"
align = @rule align("trim/{s}.fq.gz" => "bam/{s}.bam"; threads=8) =
    "bwa mem -t {threads} ref.fa {input} | samtools sort -o {output}"

run(Workflow(trim, align))                            # every sample with raw data
run(Workflow(trim, align; targets="bam/A.bam"))       # just sample A

See also @workflow, plan, check.

source
SimplePipelines.@workflow — Macro
@workflow "name" begin
    rules, steps and targets...
end

Build a Workflow from a block. Every expression that evaluates to a Rule, a Step or a vector of them is added; a string or vector of strings (that is not assigned to a variable) is a target. Assignments of other values are allowed for local helpers.

wf = @workflow "rnaseq" begin
    samples = ["A", "B"]
    @rule trim("raw/{s}.fq.gz" => "trim/{s}.fq.gz") = "fastp -i {input} -o {output}"
    @rule align("trim/{s}.fq.gz" => "bam/{s}.bam") = "bwa mem ref.fa {input} > {output}"
    expand("bam/{s}.bam"; s=samples)
end
source
SimplePipelines.expand — Function
expand(template; wildcard=values, ...) -> Vector{String}
expand(templates::AbstractVector; wildcard=values, ...) -> Vector{String}

Fill a pattern with every combination of the given values. The last wildcard varies fastest; with several templates, all combinations of the first come before the second. A single string or number counts as one value.

expand("bam/{sample}.bam"; sample=["A", "B"])        # ["bam/A.bam", "bam/B.bam"]
expand("{s}_R{r}.fq"; s=["A", "B"], r=1:2)           # ["A_R1.fq", "A_R2.fq", "B_R1.fq", "B_R2.fq"]
expand(["bam/{s}.bam", "qc/{s}.html"]; s="A")       # ["bam/A.bam", "qc/A.html"]
source
SimplePipelines.discover — Function
discover(pattern) -> Vector{Wildcards}

Find existing files matching pattern and return their wildcard values, sorted by path. Use it to check that a pattern matches what you expect, or to build sample lists:

discover("raw/{sample}_R1.fq.gz")          # [Wildcards(sample="A"), ...]
samples = [w.sample for w in discover("raw/{sample}_R1.fq.gz")]
source
SimplePipelines.Wildcards — Type
Wildcards

The wildcard values of one match, as returned by discover and passed to a Workflow filter. Read values as properties or by name:

w.sample       # "A"
w["sample"]    # "A"

SimplePipelines.plan — Function
plan(rules...; targets=String[], filter=nothing)
plan(workflow::Workflow)

Resolve rules into the concrete DAG that would run, without running anything. Print it with print_dag, run it with run, or compose it with other nodes. Errors with an explanation when a target cannot be built.

print_dag(plan(trim, align; targets="bam/A.bam"))

Running

Base.run — Function
run(node; jobs, mem_mb, min_free_mb=0, nice=10, guard=true, force=false, verbose=true,
    state_path=".pipeline_state") -> RunResult
run(rules...; targets, filter, kwargs...) -> RunResult

Run a pipeline and return a RunResult: one StepResult per step, the overall success, and the pipeline's value.

  • jobs: CPU slots (default: the CPUs this process may use). A step occupies as many slots as its threads, so at most jobs single-threaded steps run at once, however the pipeline is nested.
  • mem_mb: memory budget in MiB for the steps running at once (default: 80% of the memory this process may use; 0 = no budget). A step is charged its mem_mb, or 256 MiB when it declares none; a larger declaration is clamped to the budget.
  • min_free_mb: memory to keep free (default 0: automatic, 5% of memory between 256 and 2048 MiB). Below twice this, new steps wait; below it, the pipeline's own commands are stopped and queued again before the computer starts swapping.
  • nice: scheduling priority of the commands (0–19, default 10), so the computer stays responsive.
  • guard: enforce limits with the resource guard (default, except on Windows where it is not available). guard=false does not enforce memory limits, step timeouts or memory pressure, and cannot clean up if Julia is killed; Timeout nodes and the cleanup at the end of each step still work.
  • force: run every step even when it is up to date.
  • verbose: print progress.
  • state_path: where recipes of built outputs are remembered.

Steps with declared outputs are skipped when up to date; the others always run. A failing step stops its branch; independent branches keep going, so one bad sample does not stop the others. See Resource limits for what the guard enforces.

source
SimplePipelines.check — Function
check(node; kwargs...) -> RunResult
check(rules...; targets, filter, kwargs...) -> RunResult

Work out what run would do without running anything: expand ForEach nodes, resolve workflows, and report every step as :planned (with the reason it would run), :skipped (up to date) or :failed (a problem such as an input that does not exist and that no step produces). Takes the same keywords as run.

source
SimplePipelines.RunResult — Type
RunResult

What run and check return: a vector of StepResults in completion order, plus

  • success: whether the pipeline as a whole succeeded (a Fallback that recovered counts as success even though its primary failed); also success(result);
  • value: the value of the pipeline, e.g. the return value of a final function step;
  • duration: wall time in seconds.
source
SimplePipelines.StepResult — Type
StepResult

The record of one step in a run.

  • step: the Step.
  • label: display name, including wildcard values (align[sample=A]).
  • status: :done, :skipped (up to date), :failed, or :planned (from check).
  • success: status != :failed.
  • duration: seconds.
  • peak_mb: peak memory of the step's command in MiB, nothing when not measured (function steps, skipped and planned steps, systems where memory is not measured).
  • inputs, outputs: the declared paths.
  • result: stdout for a shell step, the return value for a function, a StepFailure when failed, the reason when planned, nothing when skipped.
source
SimplePipelines.StepFailure — Type
StepFailure(kind, message; detail="")

Why a step failed. kind is one of:

kindmeaning
:process_failedthe command exited with a non-zero status, left background processes running, or was killed from outside
:memory_limitthe command used more memory than its mem_mb and was terminated
:out_of_memorythe computer ran out of memory for this step (or the system's OOM killer stopped it)
:timed_outthe step's timeout or an enclosing Timeout expired
:stoppedthe run was interrupted, or the resource guard exited unexpectedly
:exceptionJulia code threw (message and the top of the stack trace)
:templatea placeholder cannot be filled, e.g. {mem_mb} without a declared mem_mb
:missing_inputa declared input does not exist
:missing_outputthe step finished without creating a declared output
:stdout_limitthe command printed more than 32 MiB; redirect large output to a file
:no_matchesa ForEach pattern matched no files
:unresolveda Workflow could not work out how to build a target

detail holds extra context such as the end of stderr.

Inspection and state

SimplePipelines.print_dag — Function
print_dag([io,] node; expand=true)

Print the pipeline as a tree. With expand=true, ForEach nodes are expanded and Workflows resolved against the files on disk, so you see the concrete steps that would run, with their paths and commands. A sub-DAG shared by several branches is printed once.

steps(node) -> Vector{Step}

The distinct steps of a node, dependencies first. ForEach and Workflow nodes are expanded only when they run, so they contribute no steps here; use plan to resolve a workflow first.

count_steps(node) -> Int

is_fresh(step::Step; state_path=".pipeline_state") -> Bool

clear_state!(state_path=".pipeline_state")
