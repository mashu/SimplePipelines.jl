SimplePipelines.jl

Incremental, parallel pipelines for shell commands and Julia functions, with Snakemake-style wildcard rules.

SimplePipelines takes the plumbing out of preprocessing pipelines. Declare what each step reads and writes; the package works out the order, runs independent work in parallel within your CPU and memory budget, skips what is already up to date, and tells you exactly what failed and why.

using SimplePipelines

trim  = @rule trim("raw/{sample}_R1.fq.gz" => "trim/{sample}.fq.gz"; threads=4) =
    "fastp -w {threads} -i {input} -o {output}"
align = @rule align(["trim/{sample}.fq.gz", "ref.fa"] => "bam/{sample}.bam"; threads=8) =
    "bwa mem -t {threads} ref.fa {input[1]} | samtools sort -o {output}"
calls = @rule calls(gather("bam/{sample}.bam") => "calls.vcf") =
    "bcftools mpileup -f ref.fa {input} | bcftools call -mv -o {output}"

check(trim >> align >> calls)     # what would run, and why
run(trim >> align >> calls)       # one trim and align per sample on disk, then one variant call

There is no sample list to maintain: the samples are whatever raw/*_R1.fq.gz files exist. Add a sample and rerun, and only the new sample plus the variant call run again.

What it does for you

  • Wildcards end to end. {sample} in a path is a wildcard. Targets can be patterns ("bam/{sample}.bam"): values are discovered by tracing the rules back to the source files. gather(...) collects every sample into one step.
  • Incremental builds that are correct. A step is skipped only when its outputs exist, are newer than its inputs, and were made by the same command. Edit a command and the affected steps rerun. Outputs of a failed step are removed, so a half-written file never looks finished.
  • It cannot freeze your computer. A resource guard measures every command and terminates one that exceeds its mem_mb or timeout. When memory runs low, new steps wait, and the pipeline's own commands are stopped and queued again before the system starts swapping. Steps leave no processes behind, and Ctrl-C, a closed terminal or a crash of Julia kill everything the pipeline started. Container and cluster (cgroup) limits are respected.
  • Errors you can act on. Shell commands run with bash -e -o pipefail, so a failure inside a pipe fails the step. Typos in wildcards and unknown placeholders are caught when the rule is defined. When a target cannot be built, you get the chain of missing files.
  • Low latency. Loading takes about 0.2 s. The runtime is compiled once, so your own functions add almost no compile time on the first run.
